## 0. 왜 둘로 나누나

living spec 6절 화면은 Stitch 시안을 사용자에게 확인받은 뒤에야 확정된다. 실행 중인 plan은 사람 확인을 기다리지 않으므로, 시뮬레이션 규칙과 도구를 먼저 굳히는 B1과 시안 확인 뒤의 화면 B2로 나눈다. B1을 진행하면서 시안 계획이 바뀔 수 있다.

| | B1 (이 문서) | B2 (시안 확인 뒤 별도 spec) |
|---|---|---|
| 내용 | 조정 패널, 자동 PD, 연쇄 이어받기, 렉스 수치, 카메라 자리 고정, 확률 테스트 정리 | 머리 위 감정 표시, 정보 카드, 판단 카드 감정 변화, 이어받기 표시, 정산 뿌리 줄, 로그 정보 위계 |
| 끝 | 무입력 기계 검증(자동 PD 기준) 통과 | 사용자 플레이 2회차 |

시간은 늘 몸/극 중/실제를 밝힌다. 평소(슬로모션 없음) 몸 1초 = 실제 1초, 극 중 1분 = 실제 6초(토크쇼 배율 10).

## 1. 조정 패널

### 1.1 목적

사용자가 게임을 해 보며 밸런스 수치를 바꿔 보고 감을 잡는다. 다음 파일럿에서도 그대로 쓰는 필수 도구다.

### 1.2 반영 시점

패널에서 바꾼 값은 브라우저(localStorage)에 저장되고, **새로고침 뒤 새 방송부터** 반영된다. 방송 도중에는 값이 바뀌지 않는다. 그래서 "같은 시드, 같은 조정값, 같은 입력이면 같은 결과"가 유지된다. 패널은 "지금 방송에 쓰인 값과 다음 방송 값이 다르다"를 항목마다 표시한다.

### 1.3 구조

두 층으로 나눈다.

- **일반 모듈 `src/kit/tuning/`** (게임 내용을 모른다. 다음 파일럿이 복사해 쓴다)
  - 조정 항목 정의: 키, 묶음, 쉬운 이름, 단위(시간 기준 포함, 예 "실제 초", "몸 초", "극 중 분당"), 기본값, 최솟값, 최댓값, 간격, 한 줄 설명.
  - 값 풀기: 기본값 위에 저장된 바뀐 값을 덮는다. 모르는 키와 범위 밖 값은 버리고, 버린 항목을 패널에 경고로 보인다(조용히 삼키지 않는다).
  - 저장과 불러오기(localStorage 키는 파일럿마다 다르다).
  - React 패널 컴포넌트: 묶음별 접기, 항목마다 슬라이더와 숫자 입력, 바뀐 항목 표시, 항목·전체 기본값 되돌리기, "바뀐 값 복사"(키와 값의 JSON, 코드의 기본값에 옮겨 적을 때 쓴다), "다음 방송부터 반영" 안내.
  - 단축키 `` ` ``(백틱)으로 열고 닫는다. 파일럿은 테스트용이라 모든 빌드에서 열린다.
  - 공용 패키지로 빼는 일은 두 번째로 쓰는 파일럿이 생길 때 한다.
- **게임 쪽 조정 목록 `src/content/tuning.ts`**
  - `balance.ts`의 **플레이 감각 수치**(감정, 터짐, 버릇, 연쇄, 시청률, 개입, 광고, 방송 길이), 출연자별 감정의 쌓임·빠짐 속도(`perShowMinute`, `fadePerShowMinute`), 자동 PD 수치(2절), 이어받기 창(3절)을 조정 항목으로 정의한다.
  - 스튜디오 크기, 물리 모양·마찰, 렌더, 난수 salt, 스텝 길이처럼 바꾸면 무대나 재현이 깨지는 값은 상수로 남긴다.
  - 버릇 가중치 같은 콘텐츠 값은 이번 범위 밖이다. 같은 방식으로 나중에 더할 수 있다.

### 1.4 엔진이 수치를 읽는 방식

- 반영 시점이 "새로고침 뒤"이므로, 조정값은 **페이지(또는 sim 프로세스)를 불러올 때 한 번** 풀린다. `balance.ts`의 해당 상수와 mind의 속도는 그 풀린 값에서 만든다. 그래서 상수를 import하는 22개 파일은 바뀌지 않는다.
- 한 번 불러온 뒤에는 값이 바뀌지 않으므로 그 페이지의 모든 방송이 같은 값을 쓴다(결정론 유지).
- 조정 목록 모듈은 `balance.ts`와 mind를 import하지 않는다(순환 import 방지). 기본값은 조정 목록에 있다.
- 콘텐츠 로드 검증(base spec 9.6)에 "모든 조정 항목의 기본값이 자기 범위 안에 있다"를 더한다.

### 1.5 기계 검증과의 연결

`npm run sim -- --tune <파일.json>`은 패널에서 복사한 JSON을 받아 그 값으로 무입력 검증을 돌린다. 패널에서 감으로 고른 값을 바로 게이트에 걸어 볼 수 있다.

## 2. 자동 PD (무입력 카메라 순환)

### 2.1 목적

무입력이면 와이드가 모두를 잡아 화면 밖 계열 행동(렉스 주목 욕구·코 파기·미소 연습, 프리야 휴대폰)이 거의 일어나지 않는다. 손대지 않을 때 카메라를 알아서 돌리는 "자동 PD"를 만든다. 지금은 **무입력 검증에만** 쓴다. 게임 화면은 지금처럼 수동이다. 다만 나중에 게임의 "자동 연출" 기능으로 켤 수 있는 수준으로 만든다.

### 2.2 구조

- `src/sim/autoDirector.ts`. 엔진 밖에서 `BroadcastView`를 보고, 플레이어가 내는 것과 **같은 입력**(`switch`, `track`)을 낸다. 엔진은 바뀌지 않는다.
- 난수를 쓰지 않는다. 같은 방송이면 같은 컷이다.
- 컷 순서는 쇼 데이터에 둔다(`ShowDef`의 자동 컷 순서, 카메라 id 목록). 토크쇼 기본값은 `와이드 → 클로즈업 → 와이드 → 관객석`의 반복이다. 클로즈업 차례마다 대상 출연자를 무대 순서대로 하나씩 넘긴다(이탈한 출연자는 건너뛴다).

### 2.3 컷 규칙 ("일어난 일 따라가기")

| 상황 | 동작 |
|---|---|
| 평소 | 한 컷을 몸 5초(평소 실제 5초, 실제 토크쇼 컷 4~8초에서) 잡고 다음 순서로 넘긴다 |
| 출연자가 강도 1 이상 사고를 냄 | 클로즈업 대상을 그 출연자로 맞추고 클로즈업으로 넘긴다. 그때부터 한 컷 길이만큼 잡는다 |
| 같은 출연자가 또 사고를 냄 | 컷을 유지하고 잡는 시간을 다시 센다 |
| 다른 출연자가 사고를 냄 | 지금 컷을 몸 1.5초 이상 잡았으면 새 출연자로 옮긴다. 아니면 1.5초가 지난 뒤 옮긴다(컷이 깜빡이지 않게) |
| 장비·관객이 사고를 냄 | 와이드로 넘긴다 |
| 광고 중, 방송 끝 | 아무것도 내지 않는다 |

평소 컷 길이(5), 최소 유지(1.5)는 조정 항목이다(몸 초).

### 2.4 무입력 검증의 기준 바꾸기

- `npm run sim`의 기본은 자동 PD 방송이다. living spec 7.1의 게이트를 자동 PD 방송에 건다.
- 지금까지의 고정 와이드 방송은 참고로 함께 출력하고, 게이트는 걸지 않는다(`--fixed`로 그것만 돌릴 수도 있다).
- 관객석 컷에서는 무대 사고가 송출되지 않아 정적 줄, 시청률 결과가 바뀔 수 있다. 게이트가 깨지면 조정 항목 안에서 수치를 다시 맞추고, 바꾼 값과 근거를 작업 로그에 남긴다. 수치로 맞출 수 없으면 사용자에게 보고한다.

## 3. 지시로 연쇄 이어받기

### 3.1 문제

사용자 피드백: "연쇄를 이어가고 싶을 때 피지컬 리듬게임처럼 타이밍이 촉박하다".

- 자연 연쇄의 원인 연결은 사건 뒤 몸 2초(`MOTION_CAUSE_SECONDS`)만 산다.
- 출연자 지시는 원인 없이 실행된다(`executeAction(…, null)`). 타이밍을 맞춰도 깊이 1부터 새로 시작한다.

### 3.2 규칙

- 엔진은 출연자마다 **마지막으로 연루된 사고**(강도 1 이상)와 그 스텝을 기억한다. 연루는 그 출연자가 사고를 냈거나(source), 당했거나(target), 인지했을 때(감정 인지와 같은 `perceives` 기준)다.
- 출연자 지시는 그 사고가 몸 5초 안이면 그것을 원인으로 실행한다. 깊이는 원인 깊이 + 1이다. 광고로 끊긴 연결은 넘지 않는다(기존 `linkedCauseDepth` 규칙 그대로).
- 5초의 근거: 알아채기 0.5초, 읽고 판단하기 1~2초, Space 0.5초에 여유를 더했다. 몸 시간이라 개입 슬로모션(5배) 중에는 실제 25초다. 조정 항목이다.
- 기척(강도 0)은 연루로 치지 않는다(연쇄 깊이 통계에 들어가지 않으므로).
- 지시 줄은 원인을 받는다. 예: "오카포의 버럭에 이어 렉스가 …". 문형은 narration의 원인 받기 규칙(living spec 5.2-1)을 따른다.
- 이탈(walkout) 결과, 스태프 지시는 이어받지 않는다.
- 자연 연쇄의 2초는 그대로 둔다(늘리면 무입력 연쇄가 부풀어 게이트가 깨진다).

### 3.3 화면으로 내보낼 데이터

`ActorView`에 이어받기 상태를 더한다: 원인 사고 id, 원인 문구(사고 로그와 같은 문구), 남은 몸 초. 없으면 null. 화면 표시는 B2에서 한다.

## 4. 렉스 주목 욕구 수치

- 목표: 자동 PD 무입력 방송(기본 라인업, 시드 50)의 40~60%에서 렉스 주목 욕구가 1단계에 한 번 이상 닿는다. 플레이어가 일부러 렉스를 화면에서 빼면 더 빨리 터지는 성격은 유지한다.
- 쌓임: 극 중 분당 7 → 12. 1단계 문턱 50을 화면 밖 누적 실제 약 25초에 닿게 한다(50 ÷ 25초 = 실제 초당 2 = 극 중 분당 12).
- 빠짐: 지금 극 중 분당 40(실제 초당 약 6.7). 자동 PD 방송을 측정하며 목표 비율에 들 때까지 내린다. 최종값과 측정 결과를 작업 로그에 남긴다.
- 무입력 검증에 "렉스 주목 욕구 1단계 도달 비율" 게이트를 더한다(기본 라인업 40~60%). 준 라인업은 참고로 출력한다.

## 5. 카메라 자리 고정

사용자 요청: "드래그한 다음 클로즈업 카메라로 바로 전환하고 싶은데, 위치가 바뀌니까 잘 못 찾겠다."

- 위쪽 큰 송출 모니터는 그대로 둔다.
- 아래에 카메라 3대를 쇼 데이터 순서(와이드·클로즈업·관객석)로 **항상 같은 자리**에 둔다. 송출 중인 카메라 칸은 빨간 테두리와 ON AIR 표시를 하고, 눌러도 아무 일 없다. 나머지 칸은 눌러 전환한다.
- 추적 카메라 칸은 어느 상태에서나 눌러 끌기를 시작할 수 있다.
- 숫자 키 1·2·3은 칸 순서와 같다.
- 열 폭(300px) 안에 세 칸이 들어가도록 미리보기 크기를 줄인다. 정확한 배치는 B2 시안에서 다시 볼 수 있다.

## 6. 확률에 기대는 테스트 정리

원칙(작업 로그 결정 76 뒤 테스트 원칙): "이 시드라면 몇 초 안에 터진다" 같은 확률 결과를 정답으로 박은 테스트는, 규칙이 바뀌어 난수 흐름이 달라지면 깨진다.

- `engine.life.test.ts`에서 특정 시드의 확률 결과에 기대는 통합 테스트 6~7개를 찾아 고친다.
  - 규칙을 보는 테스트는 출력을 직접 넣어 확률을 뺀다(`lifeActions.test.ts` 방식).
  - 통합 테스트로 남길 것은 재촉처럼 결과를 보장하는 규칙으로 바꾼다.
- B1의 새 테스트도 같은 원칙을 따른다. 자동 PD는 `BroadcastView`를 직접 만들어 넣고, 이어받기는 사건을 직접 넣어 확인한다.

## 7. 검증

| 항목 | 기준 |
|---|---|
| 단위·통합 테스트 | vitest, tsc, oxlint, e2e 통과 |
| 무입력 기계 검증 | 자동 PD 방송으로 living spec 7.1 게이트 전부 + 렉스 게이트 통과(두 라인업) |
