## 0. 목적과 성공 기준

exnihilo 연구소는 여러 웹 파일럿을 만들어 비교한 뒤 게임 하나를 고른다. 이 파일럿은 **"문장을 고쳐 전투를 바꾸는 손맛"과 "문장형 덱빌딩"이 재미있는가**를 판단할 수 있을 만큼의 볼륨과 난이도를 갖춘, 플레이 가능한 웹 게임이다.

성공 기준:
- 2막 런(20~30분)을 처음부터 끝까지 플레이할 수 있다.
- 지금까지 합의한 압력 장치(잉크 건조, 개입 시퀀스, 단어 오염) 덕분에 "정답 한 번 찾으면 끝"인 전투가 되지 않는다.
- 수치를 개발 패널과 데이터 파일 하나로 빠르게 조정할 수 있고, 플레이 기록이 남는다.

이미 정한 사항: 데스크톱 브라우저 대상, 한국어(조사 자동 처리), React + TypeScript + Vite + Tailwind, 애셋은 Google Stitch로 조달한다.

## 1. 전투 규칙

### 1.1 문장과 문형(Frame)

전투에는 **활성 문장이 하나** 있다. 문장은 문형이 정한 슬롯으로 구성된다. 문형은 데이터로 정의한다.

| 문형 | 틀 | 명사 슬롯 | 동사 종류 |
|---|---|---|---|
| 타동 | `S가 O를 V` | 주어, 목적어 | 타동사 |
| 자동 | `S가 V` | 주어 | 자동사 (효과 대상 = 주어 자신) |
| 수여 | `S가 O에게 X를 V` | 주어, 받는 이, 물건 | 수여 동사 (`건넨다`, `빼앗는다`→ 조사 `에게서`) |
| 환경 | `L이 O를 V` | 장소, 목적어 | 타동사 (장소는 HP 없음, 죽일 수 없음) |

- 명사 슬롯마다 **형용사 0~2개**, 동사 슬롯에는 **부사 0~2개**를 붙일 수 있다. 이 최대 개수는 `balance.ts`에서 조정한다.
- 명사와 동사 슬롯은 **교체만 할 수 있고 비울 수 없다**. 그래서 문장이 문법적으로 깨진 상태는 존재하지 않는다.
- 슬롯은 허용 품사가 정해져 있다. 주어·목적어·받는 이에는 대상 명사, 물건에는 물건 명사, 장소에는 장소 명사만 들어간다. 동사는 문형의 동사 종류와 맞아야 한다. 맞지 않는 단어는 그 전투에서 쓸 수 없다. 이 "문형 불일치 패 말림"이 경로 선택의 이유가 된다.
- 조사는 앞 단어의 받침으로 자동 결정한다(이/가, 을/를, 은/는, 에게/에게서).

**문형 변경 단어** (희귀):
- `[그리고]`: 현재 절을 복제해 두 번째 절을 붙인다. 두 절은 앞에서부터 차례로 실행된다. 이후 적의 개입은 두 절 중 어느 쪽이든 노릴 수 있다. 절은 최대 2개다.
- `[스스로]`: 타동·환경 절에 붙인다. 그 절의 목적어 슬롯이 "주어 자신"으로 고정되어 교체할 수 없게 된다. 효과는 전투가 끝날 때까지 지속된다.

### 1.2 대상 개체

- 개체: 플레이어(`당신`), 적 1~2마리, 토큰(`허수아비` 등 소환물).
- 대상 명사는 개체를 가리킨다. `당신`은 플레이어, `그놈`은 살아 있는 맨 앞 적, `저놈`은 살아 있는 맨 뒤 적, `모두`는 살아 있는 적 전체다. 토큰 명사는 해당 토큰을 가리키며, 토큰이 없으면 실행 시 소환된다.
- **적 전용 단어**: 적 고유 명사(`거미` 등), 적 전용 동사(`퍼진다`, `말소한다`), 적 전용 형용사(`끓어오르는`, `얼어붙은`), 적 장소 명사(`용암 동굴`)는 적의 초기 문장과 개입에서만 등장하고 플레이어 덱에는 들어오지 않는다. 효과는 `content/enemies.ts`에 함께 정의한다. 플레이어가 덮어쓰면 사라지고, 원문 복귀로 다시 돌아온다.
- 가리키는 개체가 없는 절(죽은 적 등)은 실행되지 않는다(불발).

### 1.3 수식어 의미 규칙

- **형용사는 슬롯에 붙고, 실행 시점에 그 슬롯에 있는 개체에게 적용된다.** 예를 들어 주어 앞의 `[눈먼]`은 "주어가 주는 피해 50%"다. 주어를 `당신`으로 바꾸면 플레이어가 눈먼 상태가 된다.
- 부사는 동사를 변형한다(배율, 반복 횟수, 부가 효과).

### 1.4 턴 순서

1. **턴 시작**: 행동력 3 충전, 4장 드로우(덱이 비면 버림 더미를 섞어 덱으로 만든다).
2. **편집**: 손패의 단어를 슬롯에 놓는다. 단어 비용만큼 행동력을 쓴다. 덮인 단어가 플레이어 단어면 버림 더미로, 적의 단어면 사라진다. **봉인**된 슬롯을 덮어쓰려면 비용이 +1이다.
3. **턴 종료**: 쓰지 않은 손패는 버림 더미로 간다.
4. **적 개입**: 예고했던 개입 단계를 실행한다.
5. **문장 실행**: 절마다 수식어를 적용하고, 동사 효과에 부사 배율과 반복을 적용해 실행한다.
6. **잉크 건조**: 보드 위 플레이어 단어의 잉크 수치가 1 줄어든다. 0이 된 단어는 버림 더미로 가고, 그 슬롯은 **원문**으로 되돌아간다. 원문은 적의 초기 문장이며, 적 개입으로 바뀐 경우 최신 적 단어다. 수식어 슬롯은 원문이 없으면 비게 된다.
7. **상태 처리**: 독은 스택만큼 피해를 주고 1 감소한다. 보호는 턴 종료 시 사라진다.
8. **승패 판정**: 적이 모두 죽으면 승리, 플레이어 HP가 0이면 패배.
9. **다음 개입 예고**: 개입 루프의 다음 단계를 공개한다.

적 개입이 문장 실행 **직전**에 적용된다는 점이 퍼즐의 핵심이다. 예고된 슬롯을 고쳐 봐야 소용없으므로 다른 슬롯으로 우회해야 한다.

### 1.5 압력 장치

- **A. 잉크 건조**: 플레이어 단어마다 `ink`(유지되는 실행 횟수)가 있다. 기본값은 2이고, 강한 단어는 1, 약한 단어는 3이다. 유리한 문장을 계속 유지하려면 비용을 계속 치러야 한다.
- **B. 개입 시퀀스**: 적마다 3~5단계 개입 루프가 있으며, 다음 1단계만 예고한다. 단계 종류는 다음과 같다.
  - `revert(slot)`: 슬롯을 적 원문으로 되돌린다.
  - `attach(slot, word)`: 수식어나 부사를 붙인다. 최대 개수가 차 있으면 가장 오래된 것을 덮는다.
  - `replace(slot, word)`: 명사나 동사를 적 단어로 교체한다.
  - `seal(slot)`: 슬롯을 봉인한다(덮어쓰기 비용 +1, 전투 동안 유지).
  - `pollute(word, n)`: 플레이어 버림 더미에 오염 단어를 n장 넣는다.
  - `enrage`: 이후 턴마다 개입 단계를 2개씩 실행한다.
  - `reframe(frame)`: 문형 자체를 바꾼다(보스 전용). 이때 문장을 적의 해당 문형 원문으로 다시 쓴다.
- **D. 단어 오염**: 오염 단어는 쓸 수 없고(비용 X) 손패만 차지한다. 전투가 끝나도 덱에 남는다. 퇴고, 상점, 이벤트로 제거한다.

### 1.6 기본 수치 (`content/balance.ts`)

| 항목 | 값 |
|---|---|
| 플레이어 최대 HP | 60 |
| 행동력 / 드로우 | 3 / 4 |
| 잉크 기본값 | 2 |
| 수식어·부사 최대 개수 | 슬롯당 2 |
| 봉인 추가 비용 | +1 |
| 강화형 적 HP 배율 (3.3 참조) | ×1.4 |

## 2. 런 구조

### 2.1 지도

- 2막이며, 막마다 7계층이다. 계층마다 노드 2~3개가 있고, 인접 계층 노드끼리 연결된다(시드 기반 절차적 생성).
- 계층 1: 전투만. 계층 5: 엘리트 노드를 1개 보장. 계층 6: 휴식 노드를 1개 보장. 계층 7: 보스.
- 나머지 노드 가중치: 전투 55%, 이벤트 15%, 휴식 15%, 상점 15%.
- **문형 결정 모드** (개발 패널에서 전환):
  - `path`(기본): 전투 노드에 적 초상화와 문형 아이콘이 보인다. 경로를 고르는 것이 곧 문형 선택이다.
  - `random`: 노드에는 `?`만 보이고, 진입 시 적이 공개된다.
- 노드 데이터는 확장 가능한 형태로 둔다(나중에 노드별 아이템, 수식 등을 붙일 수 있게).

### 2.2 노드 종류

- **전투 / 엘리트 / 보스**: 막에 맞는 적 풀에서 뽑는다. 같은 막 안에서는 같은 적이 연속으로 나오지 않는다.
- **휴식**: 퇴고(단어 1개 영구 제거)와 회복(최대 HP 30%) 중 하나를 고른다.
- **상점**: 단어 3개(일반 40 / 고급 70 / 희귀 110골드), 유물 1개(150골드), 단어 제거 1회(75골드).
- **이벤트**: 3~4종이며, 텍스트와 선택지로 구성된다(4장 참조).

### 2.3 보상

- 전투 승리 시 골드(일반 15~25, 엘리트 40, 보스 80)와 단어 보상을 받는다.
- 단어 보상: 후보 3개 중 1개를 고르거나 건너뛴다. **마지막 문장에 붙어 있던 수식어·부사 2개마다 후보가 +1개**(최대 5개) 늘어난다.
- 엘리트와 보스는 유물 1개를 추가로 준다(3개 중 1개).
- 희귀도 확률: 일반 70% / 고급 25% / 희귀 5%. 엘리트는 고급 이상 확률이 2배다.

### 2.4 문장 상속

승리 시 마지막 문장에서 **플레이어가 놓은 수식어 또는 부사 1개**를 골라 상속할 수 있다(선택 안 함도 가능). 상속한 단어는 다음 전투 시작 문장의 같은 역할 슬롯(주어 수식, 목적어 수식, 동사 수식)에 미리 놓인다. 잉크는 가득 찬 상태다. 상속 단어는 덱과 무관한 임시 복사본이라서, 건조되거나 덮이면 버림 더미로 가지 않고 사라진다. 다음 문형에 해당 역할이 없으면 상속은 사라진다.

## 3. 콘텐츠

### 3.1 시작 덱 (10)

`당신 ×2, 그놈, 허수아비, 물어뜯는다, 막는다, 치유한다, 잠든다, 눈먼, 격렬하게`

### 3.2 단어 풀 (약 50, 오염 단어 제외)

비용(c)과 잉크(i)는 따로 표기하지 않으면 c1, i2다.

| 분류 | 단어 |
|---|---|
| 대상 명사 (7) | 당신, 그놈, 저놈, 허수아비(토큰 HP 8), 돌골렘(토큰 HP 15, c2), 그림자(토큰 HP 1, 공격 시 피해 2배 반사), 모두(희귀, c2, i1) |
| 물건 명사 (6) | 저주(받는 이 취약 2턴), 축복(받는 이 힘 +2), 보호(보호 8), 독(독 4), 힘(힘 +1 영구), 잉크(행동력 +1 다음 턴) |
| 장소 명사 (4) | 얼음 호수(목적어 빙결: 다음 행동 1회 무효), 고요한 서고(목적어가 플레이어면 다음 턴 행동력 -1, 적이면 다음 개입 1단계 무효), 가시덤불(목적어 피해 5), 빛의 성소(목적어 회복 6) |
| 타동사 (8) | 물어뜯는다(피해 6), 벤다(피해 10, c2, i1), 막는다(주어 보호 6), 치유한다(목적어 회복 5), 삼킨다(피해 4 + 흡혈), 밀쳐낸다(피해 3 + 목적어의 다음 개입 1단계 건너뜀, c2), 가둔다(목적어 빙결), 지운다(희귀: 목적어 슬롯의 형용사 전부 제거 + 피해 4) |
| 자동사 (5) | 잠든다(주어 다음 실행 1회 불발), 부풀어 오른다(주어 최대 HP·HP +5), 무너진다(주어 피해 10), 분노한다(주어 힘 +2), 숨는다(주어 보호 10) |
| 수여 동사 (2) | 건넨다(물건 효과를 받는 이에게), 빼앗는다(받는 이의 해당 상태를 주어에게 옮김, 조사 에게서) |
| 형용사 (8) | 눈먼(주는 피해 50%), 독을 뿜는(가하는 피해에 독 2 추가), 단단한(받는 피해 -3), 거대한(주는 피해 ×1.5, c2), 금이 간(받는 피해 ×1.5), 굶주린(주는 피해 +3, 자신 피해 1), 빛나는(실행 후 회복 2), 끈적한(실행 후 보호 0으로) |
| 부사 (6) | 격렬하게(×1.5), 두 번(2회 실행, c2, i1), 천천히(×0.5, i3), 조용히(실행 후 개입 예고 1회 재추첨), 거듭(이번 전투 실행 횟수만큼 +1 피해), 기어이(불발 무시) |
| 특수 (2) | 그리고(희귀, c2, i3), 스스로(희귀, c2, 영구) |

희귀도는 시작 덱 단어와 기본 동사·형용사가 일반, 수치가 큰 것이 고급, 문형을 바꾸거나 전체에 작용하는 것이 희귀다. 정확한 배정과 수치는 `content/words.ts`에서 관리한다.

**오염 단어 (4)**: 거미줄, 포자, 저주받은 잉크(손패에 있으면 턴 종료 시 피해 2), 불씨(손패에 있으면 턴 시작 행동력 -1).

### 3.3 적 (12)

| 막 | 구분 | 적 | 문형 | 초기 문장 | 개입 루프 |
|---|---|---|---|---|---|
| 1 | 일반 | 거미 (HP 30) | 타동 | [독을 뿜는] 거미가 당신을 물어뜯는다 | revert(주어) → attach(동사, 격렬하게) → pollute(거미줄,1) |
| 1 | 일반 | 슬라임 (HP 34) | 자동 | 슬라임이 부풀어 오른다 (3회 부풀면 터져서 플레이어 피해 15) | revert(동사) → revert(동사) → attach(주어, 끈적한) |
| 1 | 일반 | 포자 군락 (HP 26) | 자동 | 포자 군락이 퍼진다 (실행 시 오염 포자 1장) | pollute(포자,1) → revert(동사) → seal(동사) |
| 1 | 일반 | 마녀 (HP 32) | 수여 | 마녀가 당신에게 저주를 건넨다 | revert(받는 이) → revert(물건) → pollute(저주받은 잉크,1) |
| 1 | 일반 | 고블린 도둑 (HP 28) | 수여 | 고블린이 당신에게서 보호를 빼앗는다 | revert(주어) → replace(물건, 힘) → revert(동사) |
| 1 | 엘리트 | 쌍둥이 기사 (HP 각 30) | 타동 + 그리고 | 기사가 당신을 벤다, 그리고 기사가 당신을 벤다 | revert(1절 주어) → seal(2절 동사) → revert(2절 주어) → enrage |
| 1 | 보스 | 침묵의 사서 (HP 80) | 타동 | 사서가 당신을 말소한다 (말소한다: 피해 8 + 목적어가 플레이어면 손패 1장 버림) | seal(목적어) → attach(동사, 격렬하게) → pollute(저주받은 잉크,2) → revert(주어) → enrage |
| 2 | 일반 | 화염 정령 (HP 32) + 용암 동굴 | 환경 | [끓어오르는] 용암 동굴이 당신을 삼킨다 | attach(장소, 끓어오르는) → revert(목적어) → pollute(불씨,1) |
| 2 | 일반 | 서리 망령 (HP 30) + 얼음 호수 | 환경 | [얼어붙은] 얼음 호수가 당신을 가둔다 | revert(목적어) → replace(동사, 삼킨다) → seal(장소) |
| 2 | 일반 | 거울 인형 (HP 36) | 타동 | 거울 인형이 당신을 벤다 (실행 후 주어와 목적어를 자동으로 맞바꿈) | revert(동사) → attach(목적어, 금이 간) → revert(주어) |
| 2 | 엘리트 | 검열관 (HP 70) | 타동 | 검열관이 당신을 말소한다 | seal(동사) → seal(목적어) → pollute(거미줄,2) → enrage |
| 2 | 보스 | 첨삭자 (HP 130) | 타동 → 수여 → 자동 순환 | 첨삭자가 당신을 벤다 | reframe(수여) → revert(받는 이) → reframe(자동) → revert(동사) → reframe(타동) → enrage |

2막 일반 전투에서는 1막 일반 적이 "강화형"(HP ×1.4, 개입 루프 마지막에 enrage 추가)으로도 섞여 나온다.

## 4. 아키텍처

### 4.1 구조

```
pilot-sentence/
├─ src/
│  ├─ engine/           # 순수 TS, React 의존 없음
│  │  ├─ grammar/       # 문형 정의 해석, 조사 처리, 문장 → 표시 텍스트
│  │  ├─ sentence/      # 보드 상태, 배치/덮어쓰기, 봉인, 잉크 건조, 원문 복귀
│  │  ├─ resolve/       # resolveSentence: 보드 + 개체 → Effect[]
│  │  ├─ combat/        # 턴 진행, 개입 루프, 상태, 승패
│  │  ├─ run/           # 지도 생성, 보상, 상점, 휴식, 이벤트, 상속, 유물 훅
│  │  └─ rng.ts         # 시드 RNG
│  ├─ content/          # 데이터: words, frames, enemies, relics, events, balance
│  ├─ store/            # useReducer 기반의 얇은 store
│  └─ ui/               # Title, Map, Combat, Reward, Shop, Rest, Event, RunEnd, DevPanel
├─ public/assets/       # Stitch 일러스트
├─ stitch/              # Stitch 시안 원본(참고용)
└─ tests/e2e/           # Playwright 스모크 테스트
```

### 4.2 데이터 흐름

- UI는 `dispatch(action)`만 호출한다. 엔진 `reduce(state, action): { state, events }`는 순수 함수다.
- `events`(GameEvent 목록: 개입 적용, 피해, 회복, 건조, 불발, 거부 등)를 UI가 순서대로 애니메이션으로 재생한다. 재생 중에는 입력을 막는다.
- 무작위는 전부 `state.rng`(시드 + 커서)를 거친다. 같은 시드와 같은 행동이면 같은 결과가 나온다.

### 4.3 핵심 타입 (초안)

- `Frame { id, clauses: SlotDef[] }`, `SlotDef { role, accepts: WordKind[], particle: ParticleKind, maxModifiers }`
- `Word { id, text, kind, cost, ink, rarity, effect: WordEffect }`. `WordEffect`는 판별 유니온(discriminated union)이다.
- `EnemyDef { id, name, portrait, hp, frame, initialSentence, interventionLoop: InterventionStep[] }`
- `RelicDef { id, name, hooks: Partial<RelicHooks> }`. 엔진의 정해진 지점(드로우 수, 잉크, 실행 후 등)에서 유물 훅을 호출한다.

### 4.4 에러 처리

규칙상 불가능한 행동(품사 불일치, 행동력 부족, 봉인 비용 부족)은 상태를 바꾸지 않고 `rejected` 이벤트를 돌려준다. UI는 슬롯을 흔들어 표시한다. 엔진은 게임 규칙 때문에 예외를 던지지 않는다. 예외는 콘텐츠 데이터 오류 같은 프로그래머 오류에만 쓴다.

### 4.5 테스트

- Vitest(엔진): 조사 처리, 문형별 실행 결과, 형용사 슬롯 규칙, 개입 단계 7종, 잉크 건조와 원문 복귀, 오염, 그리고/스스로, 지도 생성 재현성, 보상 후보 수, 상속.
- 콘텐츠 검증 테스트: 모든 적의 초기 문장이 자기 문형에 맞는지, 모든 단어 효과가 처리되는지 확인한다.
- Playwright: 개발 패널의 "자동 승리"를 써서 1런을 끝까지 진행하는 스모크 테스트 1개.

## 5. 애셋 파이프라인 (Google Stitch)

- Stitch 프로젝트: `projects/13834944952461605435`. 전투 화면 시안 `battle-v1`은 이미 만들어 두었다.
- 화면 시안 6개(타이틀, 지도, 보상, 상점, 휴식, 이벤트)는 전투 화면의 디자인 시스템을 재사용해 생성한다. 레이아웃과 Tailwind 토큰을 React 컴포넌트로 옮기고, HTML을 그대로 붙여넣지는 않는다.
- 일러스트는 "도감 화면" 프롬프트로 초상화 여러 장을 한 번에 생성한다. "no text in images"를 명시하고, `lh3.googleusercontent.com/aida-public/<id>=s0`으로 원본(1408×768)을 받는다.
  - 필요 수량: 적 12장(거미 완료), 탐험가 1장(완료), 막 배경 2장(동굴 완료), 이벤트 삽화 4장.
  - 글자가 박힌 이미지 등 불량품은 해당 장만 다시 생성한다.
- 아이콘은 Material Symbols(Apache 2.0)를 쓴다.
- `pilot-sentence/assets/CREDITS.md`에 이미지별 Stitch 화면 ID와 프롬프트를 기록한다.

## 7. 범위

**완료 기준**
- 2막 × 7계층 런을 처음부터 끝까지(승리 또는 사망) 플레이할 수 있다.
- 4개 문형과 그리고/스스로 변형, 적 12종, 단어 약 50개, 오염 4종, 유물 10개, 상점, 휴식, 이벤트 4종이 모두 동작한다.
- 엔진 Vitest와 Playwright 스모크 테스트가 통과한다.
- `npm run dev` 하나로 실행된다.
